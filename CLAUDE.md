# Steel Rampage

Twisted Metal-style arena vehicular combat game for the web. Single-player vs AI bots today; architected for online multiplayer later.

## Commands

- `npm run dev` — Vite dev server (port 5173). Also launchable via `.claude/launch.json` (name: `steel-rampage`).
- `npm run build` — typecheck (`tsc`) + production build.
- `npx tsc --noEmit` — typecheck only.

## Stack

Three.js (rendering) + Rapier `@dimforge/rapier3d-compat` (physics, WASM) + Vite + TypeScript. No external assets — cars, arena, textures, particles, and audio are all procedural.

## Architecture

The simulation is deliberately separated from rendering so server-authoritative netcode can slot in later:

- `src/main.ts` — bootstrap, menu, fixed-timestep loop (60 Hz sim via accumulator, per-frame render).
- `src/game/game.ts` — match coordinator: weapons (hitscan MG, homing missiles), damage/kills/respawns, lock-on targeting, ram damage via Rapier collision events, camera (chase + occlusion raycast + shake), win condition. `step(dt, input)` is the sim; `render(dt)` is visuals-only.
- `src/game/vehicle.ts` — raycast-suspension arcade car physics. Key design: **yaw-rate controller** (steering commands a target yaw rate; torque drives toward it) instead of relying on tire forces alone — this is what makes handling feel tight and prevents spin-outs. Suspension/grip/drive forces are applied per-wheel as impulses scaled by body mass.
- `src/game/bots.ts` — AI: target selection (grudge > player-bias > nearest), obstacle-avoidance ray, unstuck reverse, burst fire, pickup-seeking when low.
- `src/game/arena.ts` — physics colliders + meshes for the arena, spawn points, pickup locations, lighting.
- `src/game/specs.ts` — car archetype tuning table (speed/armor/grip per car).
- `src/render/` — procedural car meshes (box-built per archetype), particle/tracer/explosion effects.
- `src/audio/sfx.ts` — procedural WebAudio SFX (no audio files). Init requires user gesture (start button).
- `src/ui/hud.ts` — DOM-based HUD: bars, scoreboard, kill feed, radar canvas, hit feedback.

## Conventions & gotchas

- Car forward is **-Z**; steer input positive = left. Yaw quaternion helpers in `vehicle.ts`.
- All gameplay forces are impulses scaled by `dt` and body mass — never per-frame forces.
- Rapier ray hits: use `(hit as any).timeOfImpact ?? (hit as any).toi` (API renamed across versions).
- `window.__game` is a debug handle set on match start — used for headless testing via `game.step(1/60, mockInput)`.
- Vehicles get 3s spawn protection; firing cancels it.
- The preview browser tab throttles rAF when backgrounded — test physics by manually stepping `__game.step(...)` in an eval, never by wall-clock waiting.

A separately generated AI wheel (`hellcat-wheel.glb`, 13.7MB→440KB) mounts on the normal steer/spin rig. `WHEEL_YAW_BY_FILE` keyed by FILE not build (several builds share one wheel model — rotating a shared group moves them all); AI wheels come out axle-on-Z, rig wants X. Wheel loading is now fault-tolerant (`load().catch(()=>null)` + fallback to wheel-default) — a missing wheel file used to take the ENTIRE car library down to procedural.
**BLENDER GOTCHA**: `bpy.ops.object.*` fails with "context is incorrect" when the scene is left in Edit Mode — force Object Mode and clear the scene via `bpy.data.objects.remove`, not `select_all`.
**ARENA PBR**: `applyArenaPBR` + `boxProjectUVs` in arena.ts swap flat GLB wall materials for Poly Haven photoscans (brick_wall_001 / concrete_block_wall / corrugated_iron_02, diff+nor_gl+rough in public/textures). Keyed by GLB material name (`PBR_BY_MATERIAL`: Brick/Terra/Cream/BldgWall/Wall/TunnelWall/WhWall/WhWall2/Tank). CRITICAL: the GLBs bake transforms into vertex data, so mesh positions ARE world coords → box projection by dominant normal axis gives correct real-world tile scale. The original per-face 0..1 box UVs would stretch one brick tile across a whole 12m wall. Emissive/neon/glass left untouched. envMapIntensity 0.95 and brighter docks tints because the neon-night preset has so little ambient that mid-grey walls render pure black.
**POWER LIGHTS**: `Effects.glow(key,pos,color,intensity,distance)` — lazily created, reused, eased point lights driven per render frame; game.render drives 'flame' and 'turbo' for the PLAYER ONLY (each extra light costs across every lit material). Explosions already had the one-shot `flashLight`.
Phase 3.3 (done): **the whole 8-car fleet is AI-generated.** Seven more vehicles through the phase-3.1 pipeline (hero 3/4 front → reference-locked rear + side → `multi_image_to_3d`): viper/scorch/rampart/juggernaut/mortis/medic/jackrabbit `-ai.glb`, 1.2–1.7MB each after `resize --width 1024` + `webp`. All 8 builds are in `AUTHORED_TEXTURES` + `MODEL_YAW: -π/2`; all share `hellcat-wheel`.
**WHEEL CUT, PROPERLY**: `tools/blender/autocut_wheels.py` was rewritten — it used to produce files that still had their tyres, so every car rendered with EIGHT wheels (baked tyres in the arches + rig wheels hanging below). Root cause: **boolean DIFFERENCE inverts on these shells.** They are not watertight and their winding is inconsistent, so EXACT decides the outside is the inside and KEEPS the knife (measured: 23882 → 2989 tris, car gone, cylinder left, bbox reaching the knife's outer end); merge-by-distance + recalc-normals helped but still inverted on 2 of 4 wheels; the MANIFOLD solver silently returns the input unchanged. **So don't boolean — delete the vertices.** The script now selects everything inside the wheel volume and dissolves it. Wheel volume = circle of radius `R_FRAC`(0.26)×half-length centred at the contact band's X peaks, restricted to the outboard slab (|y| > 0.55×track) so the chassis floor survives. Measuring the radius from the slab was tried and overshoots badly (0.43–0.48 vs a true ~0.25) because that slab holds the whole flank; the fixed fraction is the hellcat-proven value. Removal lands at 24–52% of tris.
**WHEELS SIZED TO THE WELL**: new `src/render/wheelWells.ts` holds each body's hub geometry as reported by the cut (axleZ/trackX/hubY normalised to the scaled body). carMesh now sizes the tyre to `0.26 × halfLen × 0.9` and mounts it at the measured track/axle instead of stock constants — a stock 0.32 wheel sat lost inside these monster-truck arches. Because the visual tyre is now BIGGER than the physics `WHEEL_RADIUS` (0.26), `vehicle.ts syncVisual` lifts each wheel by `visualWheelRadius - WHEEL_RADIUS`; without it the tyre hung 0.19m under the road. `buildCarMesh` returns `CarMeshResult {group, wheels, wheelRadius}`. Physics is untouched — handling is identical.
Kit polish: steel/gunmetal/rust now carry the shared scratch roughness map (flat colour read as grey plastic beside photoscan PBR bodies), and side skirts hang off the body's own sill bbox rather than the physics half-width (they were floating as detached slabs, the AI bodies being narrower than their colliders).
Axis note for future cuts: glTF is +Y-up but Blender's importer converts to +Z-up, so in the cut script UP IS Z while the same mesh is Y-up in the browser. Model +X → car +Z after MODEL_YAW, nose at −Z.
Verified: all 8 bodies correct orientation/scale, wheels filling arches and resting on the road, 60s bot soak 887–1262m with kills flowing and no errors.

Phase 3.4 (done): power VFX, arena clutter, damage states.
**PARTICLES REBUILT ON SPRITES**: `render/spriteBatch.ts` is an InstancedBufferGeometry of quads billboarded in the vertex shader; `render/particleAtlas.ts` generates two 4x4 atlases from value noise at load (additive: 8-frame fire flipbook + glow/spark/ring/ember; alpha: 16 smoke puffs). THREE.Points could not do per-particle rotation, flipbook frames, velocity-aligned sparks, or world-unit sizes, so explosions read as additive confetti. Explosions are now a flipbook fireball + lingering smoke plume + arcing embers + a ground-plane blast ring; flames/turbo share the fire flipbook; MG gained a muzzle flash. The `Effects` API is unchanged so game.ts barely moved. `aFlat` in the instance attributes makes a quad lie in the ground plane — a billboarded blast ring reads as a vertical hoop.
**ATLAS GOTCHAS**: CanvasTexture defaults to `flipY`, which makes the shader's cell-row offset select the MIRRORED grid row — fire sampled the empty cells 12-15 while the "embers" were quietly drawing fire frames. Set `flipY = false` on atlases. Also every cell must taper its alpha at the margins or any shape touching the border gets cut square by the quad edge.
**ARENA CLUTTER**: `game/scatter.ts` adds ~5500 collider-less instances (rubble, grit, dry weed tufts, litter, kerbside tyres/pallets, road oil stains) in 7 draw calls, with per-instance tint. Placement validates against an occupancy grid built from the scene's own mesh bounds — NOT physics raycasts, because Rapier's query pipeline is empty until the first `world.step()` and buildArena runs long before that, so every cast returns null. Occupancy ignores anything large in BOTH horizontal axes (ground, sky dome, skyline, water) but keeps long thin walls. TWO TRAPS: the GLB arena path returns EARLY, so scatter must be invoked there as well as on the procedural fallback; and a wide placement band spreads the budget over the whole map and reads as a sprinkle — concentrating within 13m of a road edge is what makes it look deliberate.
**DAMAGE STATES**: below 55% health a car trails smoke, below 25% it burns (`effects.engineFire`) and the player gets a `selfFire` glow. Readability as much as juice — you can see who is worth chasing without a lock. Emission rates are PER SECOND (`rate * dt`): these run in `render()`, which ticks at the display refresh rate, so a per-frame chance would pour double the smoke on a 120Hz screen.
Verified: 90s bot soak 1082-1757m, kills crediting (2 deaths -> 2 scores), 0.35ms per combined sim+render frame, no errors.
